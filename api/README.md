# RatiteRun API

REST-бэкенд приложения RatiteRun. Чистый PHP 8.1+ без фреймворка, MySQL 8.

Контракт: [`openapi.yaml`](openapi.yaml) — 34 пути, 50 операций.

---

## Требования

| Компонент | Версия | Зачем |
|---|---|---|
| PHP | 8.1+ | enum'ы, `readonly`, `never`, именованные аргументы |
| MySQL | 8.0+ | JSON-колонки, `CHECK`, `INSERT … AS new` |
| Расширения | `pdo_mysql`, `json`, `mbstring`, `openssl`, `gd` | БД, JWT, обработка фото |

Composer не нужен — PSR-4 автозагрузчик свой, внешних зависимостей нет.

## Установка

```bash
cp .env.example .env
```

Заполнить `.env`. Обязательное — `JWT_SECRET`:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

Создать базу и накатить схему. **Два способа, любой на выбор.**

*Способ 1 — один файл.* Подходит для хостинга с phpMyAdmin, где PHP CLI недоступен:
импортировать [`install.sql`](install.sql) в созданную базу. Файл содержит всю
схему (15 таблиц), справочные данные и отметку о применённых миграциях, поэтому
`bin/migrate.php` после него ничего не продублирует. Повторный импорт безопасен.

```bash
mysql -u ratiterun -p ratiterun < install.sql
```

*Способ 2 — миграции.* Если есть доступ к консоли:

```bash
mysql -u root -e "CREATE DATABASE ratiterun CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

```bash
php bin/migrate.php
```

Проверка, что база встала:

```bash
mysql -u ratiterun -p -e "SELECT COUNT(*) FROM ratiterun.species_presets;"
```

Ожидается `3`. Если 0 — справочные данные не импортировались, движки оценки
работать не смогут.

Каталоги под файлы:

```bash
mkdir -p storage/photos storage/reports && chmod -R 775 storage
```

Функциональная проверка — 121 сквозная проверка против реальной БД:

```bash
php bin/smoke.php
```

Транспорт и подпись токенов — 14 проверок в боевом режиме (`FORCE_HTTPS=true`):

```bash
php bin/security-check.php
```

## Веб-сервер

Корень документа — **`public/`**, не корень проекта. Иначе `.env` и `storage/`
станут доступны по HTTP.

**Nginx + PHP-FPM:**

```nginx
server {
    listen 443 ssl http2;
    server_name api.ratiterun.online;

    root /var/www/ratiterun/api/public;
    index index.php;

    client_max_body_size 13m;   # загрузка фото

    location / {
        try_files $uri $uri/ /index.php$is_args$args;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
```

**Apache** — `.htaccess` в `public/` уже готов, нужен только `mod_rewrite`.

## Крон

```cron
0 4 * * * php /var/www/ratiterun/api/bin/cleanup.php
```

Чистит просроченные refresh-токены, ключи идемпотентности, окна rate-limit
и отчёты с истёкшим сроком (вместе с их PDF на диске).

### Модель данных

Стадо — агрегат. Секции (`housing`, `fencing`, `feed`, …) лежат JSON-колонками
1:1 со Swift-структурами из `Models.swift`: у них нет собственного жизненного
цикла, а такое хранение убирает трение при переносе модели. Нормализованы
только настоящие коллекции со своим `id` — `bird_records`, `reminders`,
`layout_items`.

### Движки оценки

`src/Domain/Engines.php` — построчный порт `Engines.swift`. Приложение считает
готовность локально ради мгновенного отклика при вводе, сервер — для отчётов и
будущего веб-доступа. **Формулы обязаны совпадать**: расхождение вердикта между
экраном и PDF пользователь заметит сразу. При правке одного файла правьте второй.

Веса общей готовности: пространство 25%, ограждение 20%, рацион 20%,
безопасность 15%, вода и гравий 10%, здоровье 10%.

### Нормативы по видам

Таблица `species_presets` — то, что сейчас зашито в `Presets.swift`. Правка
рекомендованной площади на птицу или высоты забора больше не требует релиза
в App Store: клиент тянет справочник по `GET /v1/species-presets` с `ETag` и
кэширует. То же для текстов — таблица `content_blocks` (дисклеймер о
безопасности, правила обращения).

### Аутентификация

Обещание приложения «no account, no sign-up» сохранено: `POST /auth/anonymous`
принимает идентификатор устройства и выдаёт пару токенов, пользователь ничего
не заполняет. Apple ID — опциональная надстройка для синхронизации между
устройствами.

Refresh-токен ротируется на каждое обновление, в базе лежит только SHA-256.
Повторное использование отозванного токена гасит всю цепочку пользователя —
защита от кражи.

### Конкурентный доступ

Полный агрегат отдаётся с `ETag` (целочисленная версия). Записи принимают
`If-Match`; расхождение — `412` с актуальной версией в заголовке. Клиент
перечитывает ресурс и повторяет.

`POST` принимают `Idempotency-Key`: повтор после обрыва связи возвращает
сохранённый ответ вместо дубликата. Тот же ключ с другим телом — `409`.

### Публичные страницы

Живут **вне** префикса `/v1`, чтобы адреса были человеческими:

| Адрес | Что это |
|---|---|
| `ratiterun.online/` | краткая главная — чтобы ссылки в шапке и в App Store не вели в 404 |
| `ratiterun.online/privacy-terms` | политика конфиденциальности и условия использования |
| `ratiterun.online/support-form` | форма обращения, записи падают в `support_requests` |

Страницы не подключают ни одного внешнего ресурса и не содержат скриптов —
именно поэтому CSP получился строгим (`default-src 'none'`).

Форма защищена связкой: CSRF по схеме double-submit cookie (HttpOnly +
SameSite=Strict), скрытая ловушка для ботов, лимит по адресу и отдельный
потолок в 5 обращений с одного IP за час. Заполненная ловушка получает экран
успеха — бот не должен понять, что его отсеяли.

Из приложения то же обращение уходит через `POST /v1/support`: там роль
CSRF-токена играет access-токен.

**Текст политики описывает ровно то, что делает код.** Перечень собираемых
полей сверялся с миграциями и контроллерами. При добавлении сбора чего-то
нового `src/View/PrivacyPage.php` нужно править вместе со схемой.

### Безопасность

Что сделано:

* **Только TLS.** Незашифрованный запрос к `/v1/*` отвергается с 403 ещё до
  роутинга — токен из заголовка `Authorization` не должен уйти по открытому
  каналу «за компанию» с редиректом. Страницы редиректятся на `https`
  с кодом 308. Отдаётся HSTS на год с `includeSubDomains` и `preload`.
* **Заголовки** на каждом ответе: `X-Content-Type-Options`, `X-Frame-Options:
  DENY`, `Content-Security-Policy`, `Referrer-Policy`, `Permissions-Policy`.
* **Секрет подписи проверяется на старте.** Пустой или короче 32 символов
  `JWT_SECRET` — сервис не поднимается вообще, а не работает с бесполезной
  подписью.
* **Двухступенчатый лимит.** Сначала по адресу — до обращения к БД, иначе
  поток анонимных запросов дёргал бы базу на каждой проверке токена. Потом
  поимённо, чтобы один NAT не блокировал всех за ним.
* **Refresh-токены** хранятся только как SHA-256, ротируются на каждое
  обновление, повторное использование отозванного гасит всю цепочку.
* **Только подготовленные выражения**, `PDO::ATTR_EMULATE_PREPARES = false`.
  Числа в `LIMIT` приходят через `queryInt()` с зажимом диапазона.
* **Загруженные изображения пересобираются** через GD — отбрасываются EXIF
  (включая GPS) и всё, что спрятано внутри файла. Хранилище лежит вне
  docroot, файлы отдаются только через PHP с проверкой владельца.
* **Обход каталога** закрыт в `PhotoStorage` и `ReportController`.
* **Чужие ресурсы отдают 404**, а не 403 — по коду ответа нельзя проверить
  существование чужого стада.
* **Ошибки наружу не текут**: `display_errors` выключен, детали только в лог,
  клиенту — problem+json.

Чего сознательно **нет**:

* **Certificate pinning.** Даёт защиту от подставного CA, но ломает
  приложение при плановой ротации сертификата — а откатить это можно только
  релизом в App Store. Для этого профиля риска обычный TLS уместнее.
* **Шифрование данных на уровне полей.** База шифруется на уровне диска
  средствами хостинга; отдельное шифрование записей о стадах не добавляет
  практической защиты, но ломает поиск и отчёты.
* **Отзыв access-токена до истечения.** Токен живёт час. Удалённый аккаунт
  отсекается сразу (проверка на каждый запрос), но отозвать конкретный
  выданный токен раньше срока нельзя — понадобится денилист по `jti`.
* **2FA.** Осмысленна только после того, как появятся полноценные аккаунты
  с паролем; сейчас их нет by design.

### Ошибки

RFC 9457, `application/problem+json`. Ошибки валидации адресуют конкретное поле:

```json
{
  "type": "https://api.ratiterun.online/problems/validation",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "The request body failed validation.",
  "instance": "/v1/flocks/{id}/fencing",
  "errors": { "strength": ["Must be between 1 and 5."] }
}
```

Чужие ресурсы отдают `404`, а не `403` — иначе по коду ответа можно проверять
существование чужих стад.

## Подключение iOS-приложения

Базовый URL берётся из `Info.plist`, ключ `RatiteAPIBaseURL`. Для дев-схемы
переопределяется через User-Defined Setting, править код не нужно.

Слой в приложении:

| Файл | Роль |
|---|---|
| `Networking/APIClient.swift` | транспорт, разбор problem+json, авто-refresh при 401 |
| `Networking/AuthManager.swift` | анонимная сессия, ротация токенов |
| `Networking/Keychain.swift` | хранение токенов (не UserDefaults) |
| `Networking/RatiteAPI.swift` | типизированные вызовы эндпоинтов |
| `Networking/FlockDTO.swift` | перевод JSON ↔ доменная модель |
| `Networking/FlockCache.swift` | кэш на чтение, фото отдельными файлами |
| `AppStore.swift` | диффы и отправка изменений |

`Models.swift` намеренно не тронут — иначе пришлось бы править все 18 экранов.

**Как уходят правки.** Локальный массив `flocks` остаётся источником правды для
UI, `binding(for:)` работает как раньше. Изменения диффятся против последнего
подтверждённого сервером снимка и уезжают посекционно с дебаунсом 1.5 с: экран
правит только загон — уходит только `PUT /housing`. При сворачивании приложения
дебаунс пропускается, всё отправляется сразу.

**Офлайн.** Режим — онлайн с кэшем на чтение. Без сети приложение показывает
последние загруженные данные и полоску статуса; правки останутся локальными
до восстановления связи. Полноценная офлайн-запись с очередью операций —
отдельная задача, здесь её нет сознательно.

**Перенос старых данных.** При первом запуске после обновления состояние из
`UserDefaults` (`ratiterun.state.v1`) заливается на сервер, если аккаунт пуст,
после чего старый ключ удаляется.

## Что сюда не вошло

Сознательно оставлено за рамками:

* **Офлайн-запись с очередью операций.** Выбран режим «онлайн с кэшем на
  чтение». Если приложение будут использовать в поле без связи, это первое,
  что стоит добавить: таблица исходящих операций + `/sync` с курсором.
* **Push-уведомления.** `POST /devices` принимает APNs-токен и складывает его,
  но отправки нет. Напоминания пока локальные, как и были.
* **Роли и совместный доступ.** Схема (`farms`, `memberships`) заложена в
  дизайне, но не реализована: сейчас стадо принадлежит одному пользователю.
* **Асинхронная сборка отчётов.** PDF собирается синхронно — отчёт текстовый и
  укладывается в миллисекунды. При появлении тяжёлых отчётов
  `ReportController::store` меняется на очередь и `202`.
* **Rate limit на нескольких инстансах.** Считается в MySQL фиксированным
  окном; при горизонтальном масштабировании заменить на Redis.
